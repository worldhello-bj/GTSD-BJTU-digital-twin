# CAD 整机与 strict82 虚拟控制台

本软件把最新夹持装配的完整源网格接到已有 strict82 虚拟会话。先运行 doctor，再运行 serve；浏览器通过 HTTP 查看。仅绑定 127.0.0.1，不连接实物。

## 启动

需要 Python 3.12、MuJoCo 3.3.7、numpy 2.2.6；依赖版本不符时 doctor/serve 拒绝启动。压缩包不包含软件安装器。

```sh
cd GTSD_Assembly_Console
python app/assembly_server.py doctor
python app/assembly_server.py serve
```

终端显示本机回环地址，默认 http://127.0.0.1:8778/assembly 。在运行服务的同一台机器上打开该地址；它不是公开托管站点，不能直接双击 HTML。Ctrl-C 关闭服务。原完整求解控制台在 `/`，新的整机来源/绑定视图在 `/assembly`，使用同一会话和原命令协议。

仓库研究目录可直接用现有 `console_config.json`；本交付 ZIP 已自动改为相对的 runtime/assets 路径，不依赖生产者工作目录。不要修改 runtime 下冻结的数值源码来消除身份检查。更换真实参数或模型应建立新的、明确验收的模型身份。

## 当前可操作

- 加载全部源三角，不静默减面。默认 1933 网格、1,631,316 三角；5 个互斥构型总计 1950 不同网格。
- 选择图版路线、孔径候选、是否开名义槽。构型选择仅影响查看，不改变求解器碰撞或参数。
- 网格搜索、三角面点选、定位/隔离、车辆/转向架/受电弓/夹具范围查看；逐件显示来源、对应刚体和绑定限制。
- 可视跟随仅对完整世界三角/朝向已匹配的 466 网格启用，属于 16 个非 world 原生刚体；764 个 world 固定网格保持静态。其余 703 项以琥珀静态显示，包括 170 静态参考、39 原排除柔性件、494 未绑定件。
- 运行、暂停、单步调用原 strict82；原完整页保留原有设备控制、导出与恢复功能。新页不新增导入/新建确认流程。
- 运行/单步要求身份一致、前后端合计快照年龄不超过 2.5 秒。已知会话的暂停不因快照陈旧而禁用；暂停请求立即停止续租。运行期间只在有效快照下续原 5 秒租约。网络失败不自动重复命令。
- 资源 SHA、场景成员和原生模型身份不符时停止可视绑定。断联停留在最后已验姿态并标明过期，不外推动画。

没有 WebGL 时使用原软件渲染器；超过 350,000 三角的范围明确阻止渲染并说明预算，请选择局部范围。全台架需要支持 WebGL 的浏览器。该功能实现存在，不等于已完成本轮真实浏览器验收。

## 实际验收与限制

真实 loopback HTTP 验收 40.44 秒，3 次原生积分：冷启动暂停、完整 gzip/解压源 SHA 一致、只读端点不改状态/不续租、完整 checkpoint 精确恢复及恢复后续算一致。精确采用完整 JSON 解码结构相等，未改用数值容差。每步 runtime/body_poses 和 checkpoint 均保留。

离线重放这些真实姿态，466 个绑定网格的 222,783 个顶点逐个对照独立矩阵公式，最大误差 2.22e-16 m。当前默认步长 0.0002 s，最长只到 0.0004 s；这些短验不证明长期稳定、半步收敛、实时速度或物理标定。没有把旧完整6秒缓存或旧长验结果归给这次新装配。

另外已有独立 strict82 可移动验收，含运行/暂停、单步幂等、坏身份/历史速度恢复拒绝、5秒失联暂停等；本包 `portable_acceptance` 保存结论和可复验入口。其原成功轮约160.70秒，与本轮3步不是同一个试验。

本轮正常沙箱 Chromium 因执行器 Unix socket 权限限制启动失败；官方提升执行路径又在创建环境时失败。另已通过官方云CDP读到旧课程页；新服务在执行进程内HTTP200，但同一时刻云浏览器访问8778端口返回ERR_CONNECTION_REFUSED。云浏览器本身可用，当前执行服务的回环地址不可达。因此本轮新整机的真实浏览器/WebGL画面、鼠标交互和下载尚未验收。没有关闭浏览器安全沙箱，也没有调用用户本机。Node/HTTP/矩阵测试不能替代视觉验收。

## 物理与源资料边界

新增夹持几何没有直接启用碰撞。第二站前视/俯视朝向、4079杆深度/截面、B535/横杆孔中心等图版冲突仍保留可切换候选；名义零间隙配合不是制造公差或实装证明。当前 `.blend` 身份和求解器源几何身份分开展示。

质量/重心/惯量、悬挂/气路/电机参数、轮轨接触型面及传感器标定仍包含工程假设。当前成果是可运行研究控制台及可信的部分可视映射，不是整机真实1:1或全部物理化完成证明。后续在确定接口/参数后才能提升新增接触与实机标定声明。

## 文件与复验

- `app/`：新视图、来源目录、映射合同、测试及本轮证据
- `runtime/`：223 个原冻结运行依赖，无源码改写
- `assets/whole.glb.gz`：完整源 GLB 的无损 gzip；浏览器自动解压，无需人工拼接
- `runtime/portable_console.py` 与 `runtime/evidence/`：先前独立短验入口及报告；不是新增装配物理验收
- `BUNDLE_MANIFEST.json`：每个文件 SHA-256 和尺寸
- `verify_bundle.py`：不运行求解器的完整文件检查

```sh
python verify_bundle.py
node --test app/tests/test_core.js app/tests/test_app_regressions.js
python app/tests/test_readonly_routes.py
# 需要正确版本的 MuJoCo 环境；在独立验收目录运行，避免覆盖随包证据：
python app/tests/check_live_http.py
node app/tests/check_runtime_follow.js
```

新页面共23项Node逻辑回归、6项轻量只读HTTP回归通过。Node DOM桩是测试夹具，不是用户界面的替代模型，也不是浏览器验收。`app/scripts`是生产者来源处理/打包记录，重新生成图纸派生网格仍需原CAD工程；日常运行无需这些生产路径。
