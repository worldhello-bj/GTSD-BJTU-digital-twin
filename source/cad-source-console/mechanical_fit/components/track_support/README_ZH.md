# 轨道支承机械配合：显式工程候选

## 可集成结果

- `profile_conforming_hull.json`：顺形共用支承方案，建议作为首个**手动选择**研究选项。
- `profile_flat_top_blank.json`：平顶毛坯方案，外轮廓相同、共同支承顶面更多填平；与前一方案互斥。
- 两个 profile 均提供 `remove_names` 和 `add_meshes`。顶点为世界米制 XYZ 平铺数组，索引为三角形。`group=environment`，所有质量/碰撞/求解器开关保持关闭。
- 每个 profile 从当前默认场景移除 13 网格、加入 9 网格。包含原 5 个待决完整组的 11 网格、旧 crossing 支板，以及另外发现已被源修订的 `.009` 主椅。不能单独替换一只扣头或只隐藏重叠证据。
- `fit_profile.py` 是无第三方依赖的原子集成适配器；默认源场景不变，开启候选才应用。错版本、缺组员、重复开启、同时开启两方案均拒绝。

## 确认了什么

以主分支 `c5dd336857fe7b573443bc6c1721e4883584acc5` 的真实 `catalog / whole.glb.gz`，先执行 `source_replacements.json` 的 323→326 静态修订，得到 1,936 网格。再完整应用本 profile 得到 1,932 网格。

两个方案的 9 个新网格均对完整当前默认场景复核，7 对正体积 AABB 疑点中，3 对由实际三角面相交/共面/包含测试证明分离，4 对存在分离平面。没有正体积或未决对象对。这只证明**这 9 个候选网格**相对其余显示几何的静态不穿料，不证明全道岔或整机无干涉。

`pair_disposition.json` 逐条保留原 4 对真实内部点及 XYZ 材料交叠弦长，再记录处置；该弦长不是最小平移距离。此前保守默认把 5 组留在旧位，所以“源位置候选穿料”与“当前默认正在穿料”必须区分。

## 方案依据和差异

1. station23 的两条原生轨心只隔约 94.5575 mm，两块通用 97 mm 宽椅不能作为两个独立实体同时存在。顺形方案改成一块 76.9997×191.5575×7 mm 共用支承，严格包含原两椅在源位置的全部材料；它恰好等于原材料并集，无材料删削。这里改变的是安装拓扑，图纸没有确认它就是一件实物。
2. crossing 的原 290×280×5 mm 支板，与 station03 两椅及下一根枕上的 `.009` 椅重叠。顺形连续支承包络为约 341.9698×280×7 mm，保留所有原支承材料及各源位置的轨底支承高度，新增约 105,383 mm³ 连续连接材料。平顶方案新增约 169,811 mm³。不能把原来几块独立零件继续计为独立件却仅在画面合并。
3. station01 原负侧 Ø10×16 mm 推定扣头进入护轨。两个完整扣头改为外侧法向 42.5 mm、沿轨向中心距 16 mm 的成组安装候选，轨/枕轴不动。为实际容纳两个扣头，在原椅外侧添加约 215.13 mm³ 安装材料，保证至少 1 mm 顶面投影边余量；未削薄、缩小或删除旧椅材料。
4. station03 / station23 原通用扣头的 41 mm 布置还会薄穿轨底，已纳入同一组装方案。采用明确 42 mm 外侧安装位置，station03 两头分列合并轨形外侧。六个扣头原顶点形状、三角索引、高度都保留，仅刚性平移，且全部位于各自新支承顶面内。

实际三角表面最小净距：station01 两头对外岔轨约 1.0503 mm；station03 为 0.5502 / 0.5000 mm；station23 为 0.5097 / 0.5097 mm。这是静态模型净距，没有计入公差、轮缘动态包络、拧紧工具空间或载荷。详见 `clearance_dimensions.json`。修改尺寸参数需要重生成及重验，直接改 JSON 的 config 不会重建网格。

## 来源和未确认部分

- `4ECFE / 4ED00 / 4ECFA / 4ECFC` 是分开的轨头边线，不能据此确认闭合支板轮廓、板厚或“代替几块椅”的关系。
- 已实际查看 `图片16.png`（Git blob `9597665f9578674dd38fb2ad2a7162cadf62e033`）；远端接缝的支承边界、孔位和安装方式不能可靠分辨。不从照片估尺寸，不随交付复制原照片。
- metadata 引用的 `bench_details_source_vectors.json` 未找到，未宣称读过。
- 这两个方案的共同底座、外置扣头布置及加料台阶属于**工程候选**。孔位、完整扣压机构、材料、紧固方式、强度、轮缘/维护空间仍须独立确认。无新增实装计数，无真实硬件访问。
- 当前默认轨本体仍有继承交叠，独立追加报告处理，不混入已验收支承 profile。

## 复核

`python -m unittest -v test_fit_profile`：18 项通过。覆盖原子组装、错版本、缺组、重复/互斥选择、非法网格、物理开关拒绝、闭合正体积、完整组、原扣头纯平移、安装投影和净距。

重新生成需本机 Python 环境已有 NumPy / SciPy；图示另需 Matplotlib。`build_candidates.py --source-root ... --mode conforming_hull --pitch-mm 16 --normal-offset-mm 42.5 --output ...` 仅写指定输出。`finalize_profiles.py` 将再按当前实际源默认场景核对。脚本内默认路径是本次云端材料位置；移植时应明确配置源根和实际主仓根，不将旧来源全量候选当当前默认。

`fit_before_after.png` 是从实际顶点生成的前后平面对照，无原照片。`conforming_hull/actual_default_validation.json` 与 `flat_top_blank/actual_default_validation.json` 给出全当前场景验证。
